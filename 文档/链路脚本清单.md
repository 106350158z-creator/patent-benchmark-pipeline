# EPO Benchmark 链路脚本清单

本文档列出 EPO benchmark 链路会用到的主要脚本，每个脚本只保留一句用途说明，便于后续维护时快速定位。

## 核心入口

- `scripts/run_epo_benchmark.ps1`：单个 EP 案件的一站式入口，串起 Register 抓取、文档下载、可选 OCR、benchmark input 构建、Markush 图片裁剪、LLM 分析、翻译和 HTML 渲染。
- `scripts/run_manifest_benchmark_batch.py`：按 manifest 批量运行现有 EPO benchmark 链路，并输出每个案件的状态 CSV。

## 候选与清单

- `scripts/collect_ep_application_candidates.py`：根据关键词批量收集 EP 申请候选，并生成带检索来源和分类信息的候选 manifest。

## EPO Register 抓取与下载

- `scripts/fetch-epo-main.ps1`：下载单个 EP 案件的 EPO Register main 页面，用于提取标题、申请人、申请日、状态和引用信息。
- `scripts/fetch-epo-doclist.ps1`：下载并解析单个 EP 案件的 EPO Register doclist 页面，生成后续下载 PDF 所需的文档清单。
- `scripts/download-epo-docs.ps1`：根据 doclist 和标题正则下载审查文件、原始申请文件等 PDF，并写出 `download-index.csv`。

## 文本提取与 OCR

- `scripts/extract_pdf_text.py`：从已下载 PDF 中提取可嵌入读取的文本，适合非扫描版 PDF 的轻量预处理。
- `scripts/ocr_case_batch.py`：对案件目录中的 PDF 批量执行本地 OCR，支持按 scope、include/exclude 正则、worker 数和超时筛选关键文件。
- `scripts/ocr-pdfs.py`：对指定 PDF 执行较底层的 OCR 转文本，主要作为 OCR 能力的单文件工具。

## Benchmark Input 构建

- `scripts/build_benchmark_input.py`：把 Register、doclist、OCR/TXT、原始申请文件和先文线索合并成 `*-benchmark-input.json`，是后续分析和 HTML 的数据源。
- `scripts/render_markush_pages.py`：从 benchmark input 关联的申请文件中渲染并裁剪 Markush 或 Formula 候选图片。
- `scripts/refine_benchmark_preview.py`：调用 LLM 精炼一个完整权利要求和一个 Markush 图片候选，用于提升 input 中的结构与预览信息质量。

## LLM 分析与翻译

- `scripts/generate_analysis_json.py`：用单次 LLM 调用生成完整 analysis JSON，适合较短或已裁剪过的案件输入。
- `scripts/generate_analysis_json_split.py`：把 analysis JSON 拆成 meta、novelty、inventive step、support、clarity、eligibility 多次 LLM 调用后再合并，适合正式 benchmark 跑批。
- `scripts/translate_report_lists.py`：把 analysis JSON 中的风险原因和建议动作补充为中英双语列表。

## HTML 渲染与校验

- `scripts/json_to_html_report.py`：把 analysis JSON 和 benchmark input 渲染成最终可阅读的 HTML 审查分析报告。
- `scripts/verify_report_sources.py`：校验 analysis JSON 中的 `original_text` 是否能在本地 `.txt` 来源中找到连续原文匹配。

## 维护与修复

- `scripts/upgrade_existing_analysis.py`：对已有 analysis JSON 做结构升级、字段补齐或兼容性修复。
- `scripts/sanitize_epo_html.py`：清理或规范化本地保存的 EPO HTML，减少后续解析噪声。
